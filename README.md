# QQ Codex Companion

通过普通 QQ 小号和 NapCat / OneBot 11，把本机 Codex 接入群聊与私聊。带本地管理页面、表情库、来源记忆与可手动调整的学习性格。主要面向 Windows 本机运行。

## 已实现的功能

- 群内被 @ 直接回复；允许名单中的私聊直接唤醒。静默模式可暂停聊天。
- 模拟间歇上线：默认每 60±15 分钟检查一次，最近一分钟有人聊天才进行首次接话判定，基础概率 37%；首次成功回复后活跃 5–10 分钟。概率和时间均可在管理页调整。
- 休息期间不记录普通群消息；定时上线最多读取最近 50 条，@ 唤醒最多读取最近 30 条。
- 支持真实 @ 成员、文字和图片分开发送、本地表情收藏与标签管理。
- 自动看 QQ 表情，每轮最多 5 张新图；普通图片与截图仅在明确要求时读取。聊天直接看图回复，WD Tagger 与标签整理在后台运行。
- 同一机器人账号的所有允许群聊和私聊共用记忆、习惯与学习性格，保留资料来源；原始近期上下文和短期心情按会话保存。
- 保留“性格与说话方式”编辑窗口；学习内容可审核、暂停、手动接管及回滚。新安装默认不自动开启成长功能。

## 安装与启动

需要 Node.js **24.5 或更新版本**、pnpm（验证版本 **11.25.0**）、已安装并登录的本机 Codex，以及单独安装并登录的 NapCat。仓库只提供机器人桥接源码，不附带 QQ、NapCat 安装包、模型权重或账号资料。

1. 下载或克隆本仓库，在项目文件夹中打开终端，安装依赖：

   ```powershell
   pnpm install --frozen-lockfile
   ```

2. 复制示例配置：

   ```powershell
   Copy-Item .env.example .env
   ```

   新安装使用项目内的 `records` 文件夹保存资料。可修改 `.env` 的 `BOT_RECORD_ROOT`，例如 `F:\botRecord`。未设置该变量时，程序原有默认值为 `F:\botRecord`。迁移已有安装时请保留原 `.env` 和记录位置。

   `CODEX_BIN` 应指向可运行的 Codex 程序，默认使用 `codex` 命令；Windows 启动脚本也会查找已安装的桌面程序。模型、推理强度与可选代理均在 `.env` 设置。普通 QQ 小号路线不使用示例文件末尾的官方 QQ 应用凭证。

3. 在 NapCat 登录 QQ 小号，启用 OneBot 11 **WebSocket 服务端**，监听本机地址（例如 `127.0.0.1:3001`），设置访问 Token，使用 `array` 消息格式。关闭自身消息上报。

4. 双击 **打开群友管理.cmd**，脚本会启动管理服务并打开带本机认证的页面。在“连接与允许名单”设置 WebSocket 地址、Token、主人 QQ、允许群和允许私聊的 QQ。名单默认留空，需要保存后才接入聊天。

   若 NapCat 安装于本项目的 `NapCat.*.Shell` 文件夹且只有一个有效连接，程序会自动发现配置；安装在其他位置时请在管理页手动填写连接。也可用 `pnpm start` 前台运行；本机管理入口保存在 `runtime/napcat/console-url.txt`。

5. 在已允许的群内 @ 机器人开始聊天；停止后台程序使用 **停止群友机器人.cmd**。

## 图片、记录与模型

`BOT_RECORD_ROOT` 下的 `img` 保存图片、表情和参考图，`txt` 保存设置、标签、聊天记录及记忆数据库。项目内的 `runtime` 保存管理凭据和进程信息。这些内容都被排除在 Git 提交之外。

图片处理使用 Sharp；WD Tagger 使用 ONNX Runtime，首次启用可能需要联网下载模型，之后可按设置检查更新。角色参考图需自行提供，或按需运行 `node src/setup-media.mjs` 下载预设参考图。图片出处核验是独立可选功能，可在管理页关闭；SauceNAO 需要自行配置密钥。

**共享范围：** 机器人允许的群聊和私聊共用聊天记忆，私聊保存的记忆也可能在群内被相关话题检索。管理页保留来源，并可清理记忆。当前一份记录绑定一个机器人 QQ，误切其他账号时暂停使用原记录。

## 文档与开发

本机修改完成后，双击 **同步GitHub.cmd**，写一句更新说明（也可直接回车），即可提交并上传到当前分支的 `origin` 仓库。窗口会保留同步结果。工具纳入项目源码、测试、文档和指定启动脚本，排除账号配置、聊天记录、图库、模型和安装程序；新增文件放在 `src`、`ui`、`test`、`docs` 时会自动纳入。其他位置的新文件需要自行审查并调整脚本中的发布范围。

需要先查看待同步文件时，在项目终端运行 `powershell -File .\同步GitHub.ps1 -Check`；指定更新说明时运行 `powershell -File .\同步GitHub.ps1 -Message "本次修改说明"`。已有本地提交但上次上传失败时，直接再次运行即可重试，不会重复提交。远程存在冲突时停止并保留本地提交，不强制覆盖远程内容。新电脑需要先配置 Git 提交身份并登录 GitHub。
